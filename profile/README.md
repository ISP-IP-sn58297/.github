<p>这篇按层讲搭建：先把线路、主机、代理三层分开，再逐层说两条上游怎么接、系统装什么、代理软件怎么选、端口怎么映射，最后给一份上线前的自检顺序。适合已经买到资源、准备自己动手的人。</p>
<h2>一、先把整件事拆成三层</h2>
<p>搭建看起来复杂，其实是三层：线路层决定地址从哪来，主机层决定跑在什么系统上，代理层决定怎么对外服务。</p>
<p>三层里最容易出错的是线路层，因为它的配置在服务商那边，你看不到，只能通过结果反推。</p>
<p>建议按层验收，一层不通就不要往上叠，否则出问题时根本不知道是哪层坏了。</p>

<h2>二、线路层：两条上游怎么落地</h2>
<p>双ISP的本质是地址在两条上游都有登记，物理上可能是一根线进来，也可能是两条独立链路。</p>
<p>单线双注册的形态布线简单，成本低，但上游其一出问题时切换能力有限。</p>
<p>双线接入要配策略路由，指定哪些流量走哪条，配置前先问清两条线路的网关和掩码。</p>
<h3>先确认拿到的是哪种形态</h3>
<p>服务商说双ISP时，追问一句是双线还是单线双注册，答案不同，后面的路由配置完全不同。</p>
<h2>三、系统层：装什么系统更省事</h2>
<p>跑代理服务用轻量Linux最省资源，1核1G足够跑几十个并发，除非还要跑别的业务。</p>
<p>Windows Server只在必须用图形界面软件时才选，同等配置下它占用的内存明显更多。</p>
<p>装完系统先做两件事：改时区、关掉不必要的服务，时区不对会让日志和业务时间全错位。</p>
<p>顺手把自动更新关掉，避免半夜重启打断连接，这类中断排查起来最费时间，日志里也看不出来。</p>
<h2>四、代理层：软件选型和端口</h2>
<p>常见的三类是HTTP代理、SOCKS5代理、以及带管理面板的网关程序，按业务需要选，不必全都装。</p>
<p>HTTP代理对浏览器友好，SOCKS5对非HTTP流量更通用，需要两者时用同一套程序开两个入口。</p>
<p>认证方式选账号密码就够了，别把无认证的端口暴露在公网，扫端口的行为每天都在发生。</p>

<h2>五、把地址和端口对外映射</h2>
<p>云主机要在安全组放行对应端口，物理机要在路由上做端口映射，两件事的原理一样。</p>
<p>映射时内外端口可以不同，但认证方式和协议要一致，否则连上了也传不了数据。</p>
<p>只映射业务需要的端口，管理口单独限制来源，这一步做与不做，差别在后续是否被扫。</p>
<h3>测通再交付</h3>
<p>从外部网络用另一条线路连一次，确认认证、出口地址、DNS三项都符合预期，再交给业务使用。</p>
<h2>六、上线前的自检顺序</h2>
<p>先查出口地址归属和上游信息，再查DNS是否走代理侧，最后压一轮并发看延迟是否抬升。</p>
<p>把检测结果记下来存一份，后面线路变化时才有对照，靠记忆判断几乎一定会误判。</p>
<h3>自检结果要留档</h3>
<p>自检通过后先小流量跑两三天，稳定了再往上加账号，出问题的代价会小很多。</p>
<h2>常见问答</h2>
<h3>搭建一定要用独立服务器吗？</h3>
<p>答：不一定。只跑单账号、流量不大时，代理账号就够。需要自装软件、长期挂着才考虑整台服务器。</p>
<h3>双ISP的机器能不能自己重装系统？</h3>
<p>答：多数可以，通过面板重装即可。重装后线路配置一般不变，但代理软件和端口映射要重新做一遍。</p>
<h3>一台机器能同时开多少并发？</h3>
<p>答：取决于配置和带宽，1核1G跑几十个轻量连接通常没问题，具体上限要压测，不能按理论值估。</p>
<h3>搭建好后地址会变吗？</h3>
<p>答：静态资源在租期内地址固定，重装系统一般不影响。更换套餐或退租才会收回原地址。</p>
